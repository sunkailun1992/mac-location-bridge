# 兼容矩阵

| 环境 | 构建/合成协议 | 系统定位 | 边界 |
|---|---|---|---|
| macOS 27.2 / 26B123，Xcode 27.2 / 27B52 | 本机通过 | 独立证书与受限叶信任的新鲜 Core Location 已验；另做过不同目标的旧证书对照实验 | 仅一台维护者设备；地图最终复核另行记录，不扩展为所有机器成功 |
| GitHub macos-latest、macos-15 | 由本仓库 CI 验证 | 未验 | CI 不改系统信任，不使用真实 Wi-Fi，不等于系统模拟验收 |
| macOS 13/14 | 允许构建 | P12 服务明确拒绝启动 | 缺少内存限定的 P12 导入接口 |
| 其他系统/build/设备 | 未验 | 未验 | 先预检，再本机实验，不按大版本猜测 |

验收阶段分别记录：身份文件有效、兼容设置精确匹配、locationd TLS/HTTP 请求、合成响应写出、新鲜 Core Location、目标 App 当前位置。保存目标、进程存活、端口就绪和测试通过都不能跨越这些阶段。

显式锚点的离线 SSL 评估由 CLI 调用，它的应用身份不同于 locationd。受限应用信任存在时，CLI 离线评估仍可能失败；因此报告同时给出明确范围的信任匹配和实际定位未验证字段。不能把任一字段单独写成“系统兼容通过”。

该路线依赖 macOS 的信任设置实现和未公开保证的 allowed-error 行为。系统升级可能令它失效；项目维护的价值是可定位问题、可替换适配器、可验证恢复，不是保证永久绕过平台约束。

当前构建保留上游手写 protobuf 名称映射的弃用提示，以及受限信任 helper 使用 legacy Security 应用约束 API 的 SDK 弃用提示，没有用编译开关隐藏它们。这些路径已在上述本机范围验证，但后续 SDK 移除接口仍需要适配。
