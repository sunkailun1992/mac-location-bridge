# 编码指南

Core 只管理协议、目标校验、TLS 服务和计数；不修改系统代理、信任数据库或启动特权进程。CLI 管参数和本地文件；App 管输入、展示、子进程与用户触发的 Core Location 探测。界面不复制协议解析。

数据流是本机目标输入 → 已校验坐标 → loopback CONNECT → 双域名与 TLS 校验 → ARPC/protobuf → 合成定位响应。真实定位结果从独立 `CLLocationManager` 获取，绝不从保存目标反推。

新增功能先声明消费方契约、失败方式与恢复动作，再改最小模块。修复先重现原症状，用能捕捉错误的测试或实机复现记录；不要叠加猜测性补丁。连续失败时更新假设，重新检查系统边界。

具体定位功能以 [F01–F11 及详细规则](../location-modification-spec.md) 为准，操作路径见 [operations.md](../operations.md)。修改相应行为必须同步契约、命令说明、状态门禁、恢复步骤与相关测试；不能把 Core 能力自动写成 App 已有功能，也不能把验收建议写成已实现的自动检测。

依赖必须精确固定并保留许可证。不要为了简单 CLI 引入额外框架，不把浏览器定位模拟包装成系统定位。若要新增后端/API，先定义公开契约、认证边界和本地可运行验证。
