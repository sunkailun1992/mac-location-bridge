# LocationBridge 设计

用户要求独立公开 GitHub 仓库、自行维护新版 macOS 适配，并完成本机定位模拟。用户已指定直接实施，方案选择由实现者负责。

## 目标和验收

提供 macOS 原生程序与可脚本化 CLI。保留响应构造、TLS 接入、信任设置、代理集成和实际 Core Location 验证之间的边界。一次会话只有在新鲜系统读数接近目标且独立地图验证通过后才能标为成功。界面保存目标不算成功。

## 方案

采用独立 Swift Package，按 MIT 许可证复用 WLoc 的 ARPC/protobuf 与响应构造，修复套接字所有权与日志异常。原版完整 fork 会保留 iOS、共享证书和旧特权助手负担；完全重写增加协议回归风险。选择抽取已知协议实现、独立证书与身份、原生小界面。

参考 TimBitBox 的私有模拟偏好与 SpoofGeo 的浏览器/进程注入，分别记录实际验证范围。它们尚不能作为当前系统 Core Location 成功的证据。

## 模块

- `LocationBridgeCore`：严格目标校验、ARPC/protobuf、仅双定位域名的本地 CONNECT/TLS 服务、状态计数和不含请求正文的诊断。
- CLI：生成本机唯一证书、兼容预检、服务启动、只读信任校验、实际定位探测、状态与恢复指引。
- App：目标输入、启动/停止、兼容结果与真实定位结果，失败时解释所处阶段。
- 独立受限实验：研究当前系统信任 API 是否能表达叶证书、定位服务应用、精确主机名的异常。先备份后测试，不发布未经验证的稳定支持承诺。

## 约束

macOS 13+；Swift 5.9+；SwiftProtobuf 固定 1.38.1。仅监听 loopback；只允许两个定位域名与 443；不得成为通用代理。无云端服务、遥测、内置共享私钥或用户代理订阅。保留第三方 MIT 声明。

不关闭 SIP、不修改 Apple 二进制或证书绑定数据库；不全局信任任意证书。信任与网络更改按会话记录，未知外部漂移拒绝覆盖。公开仓库只含合成测试数据，实际坐标、证书、Wi-Fi 内容与本机回执留在仓库外。

## 本轮决策和边界

先验证 macOS 27.2 的 TLS 障碍，再做真实请求和定位验证。当前尚无证据证明独立版本已解决绑定限制。若受限实验失败，恢复状态并公开准确的兼容状态，不能用浏览器模拟冒充系统定位成功。
